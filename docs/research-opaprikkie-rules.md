# Opa Prikkie rules discrepancy research

Source checked: [official rules](https://opaprikkie.nl/spelregels/) (accessed 2026-10-17).

This report records differences and questions for issue #4. It does not decide which behavior the simulator should adopt.

| Topic | Official rule | Repository behavior | Evidence | Question |
| --- | --- | --- | --- | --- |
| Physical peg count | The contents list says 26 pegs: 12 per player plus 2 spares. | README says 24 pegs, then says the physical game has 2 spare pegs. The board model creates 12 pegs per board. | Official rules, lines 31-39; [README.md](../README.md#L11-L16); [board.py](../src/opaprikkie_sim/board.py#L29-L34) | Should the README describe 26 physical pegs while keeping 12 playable pegs per board? |
| Starting player | The player with the shortest pinky finger rolls first. | `GameState.current_player_index` always starts at 0; there is no starting-player selection. | Official rules, lines 45-47; [game.py](../src/opaprikkie_sim/game.py#L41-L46) | Should starting-player selection be modeled, and if so how should it be supplied for simulations? |
| Opening roll counts | After choosing a number, the player sets aside matching dice from that roll and continues with the remaining dice. Those rolls determine the holes moved. | `Game.play_turn()` rolls once for strategy selection, then `_simulate_turn_for_target()` calls `DiceRoller.simulate_turn()`, which rolls a new full set. The opening roll is never counted toward movement. | Official rules, lines 46-51; [game.py](../src/opaprikkie_sim/game.py#L96-L129); [dice.py](../src/opaprikkie_sim/dice.py#L105-L111) | Should the initial roll be passed into turn simulation and counted? |
| New target after reaching top | If a peg reaches the top during a turn, all dice may be rolled again and the player may save for another number. | `Game.play_turn()` simulates one target, applies its movement, then advances to the next player unless the entire board is complete. There is no same-turn target selection after an individual peg reaches the top. | Official rules, lines 53-57; [game.py](../src/opaprikkie_sim/game.py#L127-L173) | Should a turn continue with a fresh target whenever its peg reaches the top? |
| No match on first roll | The player chooses a number to save after the opening roll; the rules say the turn stops when that chosen number is no longer rolled. | Strategies only return targets present in `get_available_targets()`. If no target is available, `play_turn()` records a skipped turn and changes player. | Official rules, lines 45-51; [strategy.py](../src/opaprikkie_sim/strategy.py#L34-L48); [game.py](../src/opaprikkie_sim/game.py#L102-L125) | Is choosing a target with zero matches legal, producing a zero-movement turn, or should the current skip behavior represent the intended interpretation? |
| Board display position | Pegs start on the bottom row and move upward toward the top. | `get_board_state()` writes a peg at `board[peg.position - 1]`; position 0 therefore indexes the last row, while display reverses rows and labels that row as the top (5). | Official rules, lines 37-43; [board.py](../src/opaprikkie_sim/board.py#L57-L81); [tests/unit/test_board.py](../tests/unit/test_board.py#L84-L102) | Should position 0 be rendered on the displayed bottom row, and should a display regression test be added? |

The target mapping itself agrees at a high level: 1-6 use one die and 7-12 use two dice (official rules, lines 48-50; [README.md](../README.md#L25-L33)).
